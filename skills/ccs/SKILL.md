# ccs — 세션을 git 처럼

`ccs` 는 이 저장소의 `ccs.py` 를 PATH 에 링크한 명령이다(없으면 `python3 <이 스킬 폴더>/../../ccs.py`). 판정은 로컬 파일·ps·git 만 읽고 아무것도 바꾸지 않는다.

## 판정 보기

```bash
ccs status --json      # 기계용. 사람에게 보여 줄 땐 ccs status
ccs show <이름|id앞자리|제목일부>
```

verdict 의미와 사용자에게 전할 말:

| verdict | 뜻 | 전할 것 |
|---|---|---|
| `block` 🔴 | 응답 생성 중 · Bash 명령/서버가 돌고 있음 · `/loop` 예약 · 세션 cron | 무엇 때문에 끄면 안 되는지(`blockers`)와 끝나길 기다릴지 |
| `job` 🤖 | 탭이 아닌 `claude -p` 자동 작업(부모 프로그램이 띄움) | 끄면 중단된다는 것, 부모 프로그램 이름 |
| `resume` 🟡 | 꺼도 되지만 이어서 할 일: Claude 질문에 답 안 함 · 중단됨 · 이 세션이 고친 파일 미커밋 · 이 세션이 만든 커밋 미푸시 | `pending` 과 마지막 문단 한 줄 |
| `done` 🟢 | 걸리는 것 없음 | 묶어서 "N개는 꺼도 됨" 한 줄 |

`notes` 의 "repo에 다른 미커밋 N개" 는 같은 repo 를 다른 세션·사람이 바꾼 것이라 이 세션을 끌지 말지와 무관하다. 판정 근거로 쓰지 않는다.

`is_self: true` 는 지금 대화 중인 이 세션이다. 늘 `block`(응답 생성 중)으로 나오므로 그 이유로 경고하지 않는다.

## 저장하고 닫기 · 다시 열기

- `ccs stash -m "메모"` — 목록 저장만. 바깥에 영향 없음, 물어보지 않고 해도 된다.
- `ccs stash --close` — 저장 뒤 🟢·🟡 세션 프로세스를 종료한다. **사용자가 닫으라고 한 뒤에만**, 닫을 목록을 먼저 보여 주고 `--yes` 로 실행한다. `--force`(🔴 까지 닫기)는 사용자가 그 세션을 이름으로 짚었을 때만.
- `ccs pop [--only resume,block | --all] [--dry-run]` — 저장한 세션을 각자 원래 터미널(cmux 워크스페이스·tmux 세션·Orca 작업공간)로 다시 연다. 원래 터미널이 꺼져 있으면 다른 곳으로 열고 `자리 바뀜` 으로 알린다. 이미 열린 세션은 자동으로 뺀다. 먼저 `--dry-run` 으로 열 목록을 보여 주고 확인받는다.
- `ccs stash list` — 저장 이력.
